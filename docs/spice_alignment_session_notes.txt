1. BACKGROUND
================================================================================

Gilgamesh is a Rust-based spiking neural network simulator with a SPICE export
path for hardware validation. The network architecture is:

    Input (36) -> FC1 -> LIF (12 hidden) -> FC2 -> LIF (10 output) -> Spike Count

A previous review identified 12 issues. Four were approved for fixing:
  1. Membrane equation doesn't match RC physics
  2. SPICE weight scaling is wrong
  3. v_peak default is wrong (2.6V instead of 4.44V)
  4. parse_wrdata hardcodes output_size=10

--- PHYSICS FIXES (the core of this work) ---

FILE: src/neurons/lif/forward.rs

  FIX 1: RC Membrane Equation (line ~37-40)
    OLD: mem_new = mem_prev * decay + input
    NEW: mem_new = mem_prev * decay + input * (1.0 - decay)

    Why: The correct discrete RC equation is:
      V(t+dt) = V_ss + (V(t) - V_ss) * exp(-dt/tau)
    where V_ss = input (steady-state voltage for constant drive). This expands to:
      V(t+dt) = V(t) * exp(-dt/tau) + input * (1 - exp(-dt/tau))
    The old equation was missing the (1-decay) factor, which meant at small dt
    (e.g. 1us) inputs were not attenuated at all, while at larger dt they were
    wrong by a factor of 1/(1-decay). With dt=1ms and tau=3.96ms, decay=0.777,
    so (1-decay)=0.223 — the old code overdrove neurons by ~4.5x.

  FIX 2: Pulse Charge Scaling (compute_pulse_output, line ~109-119)
    OLD: charge_scale = tau_pulse / dt
         output = v_peak * charge_scale * exp(-elapsed/tau_pulse)
    NEW: charge_scale = (tau_pulse / dt) * (1.0 - exp(-dt / tau_pulse))
         output = v_peak * charge_scale * exp(-elapsed/tau_pulse)

    Why: The pulse output represents the AVERAGE pulse voltage over one discrete
    timestep [n*dt, (n+1)*dt]. For an exponential pulse v_peak*exp(-t/tau_pulse),
    the average over timestep n is:
      v_avg = (v_peak*tau_pulse/dt) * exp(-n*dt/tau_pulse) * (1 - exp(-dt/tau_pulse))

    The old code omitted the (1 - exp(-dt/tau_pulse)) factor, overestimating
    charge delivery by 1/(1-exp(-dt/tau_pulse)). With dt=1ms, tau_pulse=0.5ms:
    old charge_scale = 0.500, new charge_scale = 0.432 (~13.5% reduction).

    This fix appears in 3 locations (forward_with_pulse, forward_full_physics,
    and the fallback immediate-spike path).


FILE: src/neurons/lif/mode.rs (line ~123)

  FIX 3: v_peak Default
    OLD: v_peak: 2.6
    NEW: v_peak: default_v_peak()  (returns 4.44V = VDD - diode_drop - comp_drop)

    Why: 2.6V was a stale placeholder. The actual hardware pulse stretcher peaks
    at VDD (5.0V) minus the diode forward voltage (0.37V) minus comparator rail
    drop (0.21V), giving ~4.42V. The default_v_peak() function computes this.


FILE: src/spice.rs

  FIX 4: Weight Scaling for VCCS (transconductance)
    OLD: current_gain = 4.0 * threshold.over_vref / membrane.r_leak
         (then gm = w * current_gain / input_scale)
    NEW: gm = w / R_leak  (for both input->hidden and hidden->output synapses)

    Why: With the corrected RC membrane equation, V_ss = I * R_leak. For a VCCS
    driving current I = gm * V_control into the membrane RC, the steady-state
    membrane voltage is gm * V_control * R_leak. We want this to equal w * V_control
    (matching Rust's fc.forward() which computes weight * input). So gm = w / R_leak.
    The old formula had an extra factor of 4 * threshold that was compensating for
    the broken membrane equation.

  FIX 5: Bias scaling
    OLD: scaled_bias = bias * current_gain
    NEW: scaled_bias = bias / R_leak
    Same reasoning as weight scaling.

  FIX 6: parse_wrdata output_size parameter
    OLD: let output_size = 10;  (hardcoded)
    NEW: fn parse_wrdata(path, output_size: usize)  (parameter)
    Also updated run_ngspice to take and pass output_size.

  FIX 7: from_network physics extraction
    OLD: Used default SpiceParams regardless of model
    NEW: Extracts tau_m, tau_pulse, threshold, dt from the actual neuron NeuronMode
    Also takes sim_duration: f32 (seconds) instead of num_steps: usize.


FILE: src/network/network.rs

  FIX 8: Pulse-aware forward_traced
    OLD: forward_traced always used binary spikes (0/1) between hidden and output layers
    NEW: When physics mode with tau_pulse > 0, uses forward_with_pulse for hidden layer
         and passes pulse output through fc2 to output layer — matching SPICE behavior

    Why: SPICE hidden->output synapses are VCCS driven by pulse_h_N (continuous
    exponential decay from ~4.4V). Rust was using binary 0/1 spikes, which is a
    completely different signal magnitude. This caused massive mismatch.

  FIX 9: Pulse-aware training forward pass (forward_quantized_full)
    Same change as above but in the training path. Binary spikes are still stored
    in cache for the backward pass (surrogate gradient), but the pulse output
    flows through fc2 weights for the output layer computation.

4. KNOWN REMAINING ISSUES
================================================================================

ISSUE A: parse_wrdata Bug
  The Rust wrdata parser (src/spice.rs, parse_wrdata function) produces wildly
  different spike counts than a simple Python parser reading the same file.
  Rust reported 81 spikes for class 3 while Python shows 5. This is the most
  immediate bug to fix. Possible causes:
  - wrdata line wrapping confusing the parser (lines are ~1500 chars)
  - f32 precision issues when parsing scientific notation values
  - Some edge case in the threshold crossing detection

ISSUE B: Rust vs SPICE Spike Count Mismatch
  Even with the correct Python parser, Rust produces significantly more spikes
  (54 vs 36) and a different prediction (4 vs 9). Sources of discrepancy:

  1. Discrete vs Continuous Integration: Rust steps at dt=1ms while SPICE
     integrates continuously at ~0.25us steps. The pulse charge_scale correction
     helps but doesn't fully account for the continuous RC response to a decaying
     exponential input.

  2. Reset Mechanism: Rust uses "subtract" reset (mem = mem - threshold), keeping
     residual charge. SPICE uses a switch to ground (Ron=10 ohm), which does a
     "zero" reset. After each spike, Rust retains ~0.1V residual while SPICE
     goes to ~0V. Over many spikes this makes Rust fire faster.

  3. Refractory Period: SPICE's reset switch stays closed while comp_pulse > 3.5V
     (about 0.12ms after each spike). During this time the membrane can't charge.
     Rust has no refractory period — it starts integrating immediately after reset.

  4. Threshold Adaptation: SPICE has a small threshold adaptation circuit
     (Cadapt + Ginj). Analysis shows this is negligible (~24uV per spike) so
     it's not a significant source of error.

  5. Pulse Shape: Rust uses a pure exponential for the pulse stretcher output.
     SPICE's actual circuit has a diode, charging resistor, and bleed resistors
     that modify the pulse shape slightly.

ISSUE C: Training Uses Different Physics Than Comparison
  The training forward pass (forward_quantized_full) may not perfectly match
  forward_traced in all code paths. Both now use pulse outputs between layers
  in physics mode, but subtle differences in state initialization or accumulation
  could cause the trained weights to be suboptimal for the exact comparison path.

ISSUE D: Old Models Broken
  The membrane equation change (fix 1) fundamentally changes the physics.
  All previously trained models (physics_h9.json, etc.) will produce wrong
  results. Only models retrained after the fix are valid.
